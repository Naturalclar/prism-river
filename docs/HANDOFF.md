# HANDOFF: Prism River を育てる

このリポジトリで作業するエージェントセッションへの引き継ぎ。

**v0 は Vite + TypeScript + React + oxlint + pnpm に移行済み**（2026-08-26）。下の「出発点」と「v0 で動いていること」は、リグレッションの基準として読む経緯の記録。

---

## 依頼

**Web 上の DAW（Logic Pro / BandLab のようなもの）がどこまで実用に足りるかを検証するための台を作る。** 音声ファイルをドラッグ＆ドロップで読み込み、マルチトラックで並べて再生・ミックスできるサイト。

**作業は全部ブラウザのローカルセッションで完結させること。** サーバーへのアップロードもアカウントも作らない。読み込んだ音声が端末から出ないことが前提で、これはプライバシー上の要件であると同時に「サーバー無しでどこまでいけるか」という検証テーマそのもの。

動く v0 は既にある。**ゼロから書き直すのではなく、それを起点にする。**

## 出発点

v0 は単一ファイル・依存ゼロ・ビルド不要の `index.html` だった（root commit `2ba3386`）。元は Artifact として公開したもの（https://claude.ai/code/artifact/ff441472-c1b9-427b-955b-813107502e48 ）で、このリポジトリに入れる際に名前と配色だけ変えてある。

**現在の正本は `src/` 以下。** v0 の挙動・見た目・計測値はそのまま移してあり、CSS は丸ごと `src/styles.css` に移動しただけ。v0 のコードを読みたいときは `git show 2ba3386:index.html`。

## v0 で動いていること（実機確認済み・2026-08-26）

Playwright で実際に音声を読ませて確認した範囲。**憶測ではなく計測値**なので、リグレッションの基準に使える。

- ドラッグ＆ドロップ／ファイル選択で**複数ファイル同時読み込み**、`decodeAudioData` でデコード
- Canvas でピーク波形描画（min/max を列ごとに畳む方式）。減衰4発の音源で振幅変化が出ることを確認済み
- 再生・停止・ループ、Space キー、ルーラークリックでシーク、`requestAnimationFrame` でプレイヘッド追従
- トラックごとに音量（GainNode）・パン（StereoPannerNode）・ソロ・ミュート・削除
- **クリップの横ドラッグで開始位置をずらせる**。再生中にずらすと即座にソースを組み直す
- マスター音量、AnalyserNode による L/R レベルメーター、ズーム（px/秒）
- `OfflineAudioContext` でミックスを一括レンダー → WAV エンコード

**計測結果（テスト音源、44.1kHz ステレオ）:**

| 項目 | 値 |
| --- | --- |
| sampleRate | 44,100 Hz |
| 出力レイテンシ | 32.0 ms |
| デコード | 2ファイルで 18 ms |
| PCM メモリ | 2トラック 4秒で 1.3 MB |
| オフラインレンダー | 4秒のミックスを **12 ms＝実時間の約323倍速** |

最後の行がこの検証の一番の収穫。**ミックスダウンは実時間の数百倍で回る**ので、書き出しの速度はブラウザだからという理由でネックにはならない。

## 既知の制約（v0 で判明済み。作り直しても消えない）

1. **`.wav` は claude.ai の Artifact ビューア上では保存できない。** ビューアの保存許可拡張子が `png jpg webp mp4 webm txt json md`（拡張セットでも `docx pptx csv svg pdf` 等）で、音声拡張子が一つも無い。**ブラウザの制限ではなくビューア側の制限**なので、**自分のドメインに置けば普通に保存できる**。v0 は `window.claude` の有無を見てビューア内なら `downloads.save()`、素で開かれたら通常のダウンロードに落とす作りになっている。リポジトリ化して自前ホストにすれば、この分岐の後半だけが効く。
2. PCM はデコード後 **Float32 で持つ**ので、`長さ(秒) × 44100 × ch × 4 bytes`。10分ステレオ1本で約 100MB。**トラックが増えるとメモリが先に効く**ので、長尺を扱うなら実測しながら上限を決めること。

## やってほしいこと

1. **次の機能を足す。** 優先度順に並べたが、検証テーマ（どこまでできるか）に効く順で選び直してよい:
   - **クリップのトリム**（左右端をドラッグして頭尻を詰める）— DAW として最低限これが要る
   - **フェードイン／アウト** — `GainNode` の `linearRampToValueAtTime` で足せる
   - **エフェクト** — `BiquadFilterNode`（EQ）と `DynamicsCompressorNode` は素で使えるので、まずこの2つ。ここが「Logic の代わりになるか」の分水嶺
   - **録音入力** — `getUserMedia` + `MediaRecorder`。マイク録りができると用途が一気に広がる
   - **実時間 webm 書き出し** — `MediaStreamAudioDestinationNode` + `MediaRecorder`。オフラインレンダーと違って実時間かかるが、対応コンテナが増える

## 決めたこと（2026-08-26・決着済み）

**Vite + TypeScript + React + oxlint + pnpm。** 本人の判断。

引き継ぎ時点の推奨は「React 無し」だった——プレイヘッドが毎フレーム動く UI に仮想 DOM を挟む利点が薄い、というのが理由。**採らなかった。** medley-generator と同じ構成に揃える方が、道具立てを一つ覚えれば両方触れるという利点が上回る。個人プロジェクトを2つ別々の作りで持つコストの方が、この規模では高い。

推奨側の懸念（再描画コストが計測に乗る）は、**構造で外してある**:

- `src/audio/engine.ts` の `Engine` が AudioContext・トラック・トランスポートを全部持つ。React には依存しない
- React は `useSyncExternalStore` で**スナップショット**（AudioNode を含まない素のデータ）を読むだけ
- プレイヘッド・時計・レベルメーターは `engine.onFrame()` を購読して **DOM を直に書き換える**。毎フレームの再レンダーは発生しない
- クリップの横ドラッグ中も `style.left` を直書きし、指を離したときだけ `commitOffset()` で React と再生グラフを組み直す

移行前後でオフラインレンダーの倍率が変わっていないこと（約323倍速 → 約309倍速、環境差の範囲）を実測で確認済み。**この構造を崩すと計測値が信用できなくなる**ので、オーディオのタイミングに関わるものを `useState` に持たせないこと。

リンタは medley-generator に合わせて **oxlint**（ESLint ではない）。**oxlint はデフォルトで警告時も exit 0 になる**ので、`lint` スクリプトには `--deny-warnings` を付けてある（medley-generator 側で実際に踏んだ罠）。

## 制約

- **音声を端末から出さない。** アップロード先を作らない。解析のための外部 API 呼び出しもしない
- **依存を安易に増やさない。** 波形描画も WAV エンコードも Web Audio と Canvas だけで足りている。ライブラリを入れるなら「自前だと何が足りなかったか」を先に書くこと
- **v0 の計測値を消さない。** 下段のテレメトリ（sampleRate / レイテンシ / デコード時間 / PCM メモリ / レンダー時間）はこの台の存在理由なので、UI を作り直す場合も同等の情報を残す
- **オーディオの状態を React に持たせない。** 上の「決めたこと」の通り、`Engine` が正本でコンポーネントは表示だけ
- 公開リポジトリにするなら、テスト用音源に**権利のあるファイルをコミットしない**

## 検証してほしいこと（v0 では未確認）

分かったことはリポジトリの README に残してほしい:

- [ ] **長尺の実測。** 5分・10分の曲を複数トラック読ませたときのメモリとデコード時間。どこで破綻するか
- [ ] **mp3 / m4a / flac / ogg の実対応。** `decodeAudioData` はブラウザのコーデックに依存するので、Safari と Chrome で違う可能性がある。ダメな形式は読み込み時にはっきり伝える作りになっているか
- [ ] **モバイル Safari。** iOS は AudioContext の起動にユーザー操作が要る、バックグラウンドで止まる等の制約が強い。実機で触ってどこまで動くか
- [ ] **レイテンシの実用性。** 録音入力を足したとき、モニタリングの遅延が演奏に耐えるか。v0 の出力レイテンシ 32ms はこの判断の入口の数字

## 命名と構造

Prism River は騒霊三姉妹から。**ルナサ＝弦 / メルラン＝管 / リリカ＝鍵盤**の編成をそのまま構造に借りている。

- トラックの先頭3色がこの3人に対応する（`src/audio/engine.ts` の `HUE`）
- 「これから」4番目の**グループバスもこの3系統で切る**予定。トラックを弦/管/鍵盤のサブミックスにまとめ、そこにエフェクトを挿す形

装飾ではなく編成の呼び名として使っているので、バスを実装するときはこの対応を崩さないこと。
